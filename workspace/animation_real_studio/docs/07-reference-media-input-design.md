# 참조 미디어 입력 설계

## 결정

P0는 텍스트 설명에 더해, 사용자가 권리를 가진 **비식별 시각 참조** 한 건을 선택 입력으로 받는다. 참조는 배경·공간, 조명·색감, 카메라 구도, 움직임 리듬을 전달하는 데만 쓴다. 인물의 정체성, 캐릭터, 원작 장면을 재현하는 입력으로 쓰지 않는다.

이 기능은 실제 생성 공급자가 해당 참조 유형을 생성 입력으로 지원하고, 보존·학습 재사용·삭제 조건을 확인한 경우에만 출시한다. 단순히 "참고용"으로 받아 놓고 생성에 쓰지 않는 UI는 제공하지 않는다.

## P0 입력 계약

| 항목 | 허용 | 제한 |
|---|---|---|
| 사진 | JPEG, PNG, WebP 한 장 | 배경·조명·구도 참고만 가능 |
| 영상 | 무음 MP4 한 개 | 최대 15초, 움직임·카메라 리듬 참고만 가능 |
| 사용 목적 | 배경/공간, 조명·색감, 카메라 구도, 움직임 리듬 | 하나 이상 선택 |
| 사용자 확인 | 제작/처리에 필요한 권리 보유, 제3자·아동·개인정보 없음 | 제출 전 필수 |

P0에서 실존 인물 사진·영상, 얼굴·음성, 아동, 애니메이션 스틸·원본 클립, 제3자 상업 영상, 저작권 음원, 로고·신분증·번호판·개인정보는 받지 않는다. "내 사진으로 캐릭터 만들기"는 본인성·연령·동의 철회·공급자 처리 계약이 필요한 P1 별도 트랙이다.

## 사용자 흐름

```text
텍스트 장면 설명 + 선택 참조 미디어
  → 업로드 격리 → 파일/메타데이터/정책 검사
  → 참조 허용 | 재작성 | 운영 검토 | 차단
  → 안전한 특징만 브리프·스토리보드에 반영
  → 사용자 승인 → 승인 참조본만 공급자에 전송 → private 전달
```

화면은 검사 결과와 `reason_code`, 다음 행동(파일 제거, 재작성, 검토 대기)을 함께 보여 준다. 예를 들어 승인된 결과에는 "비 오는 네온 골목의 저채도 조명" 또는 "느린 핸드헬드 이동"처럼 추상화한 특징만 기록하며, 원본 장면·인물의 복제를 약속하지 않는다.

## 처리와 보관

1. 업로드 직후 원본은 격리 저장소에 두고, MIME·크기·악성 파일을 검사한다.
2. EXIF GPS·기기정보와 오디오를 제거하고, 영상에서는 검사 전용 프레임만 추출한다.
3. OCR, 얼굴·아동 가능성, 신분증·번호판·개인정보, 로고, 원작 장면·음원 의심 신호를 검사한다. 모호하면 `needs-review`로 보낸다.
4. 통과 전 원본·프레임·오디오를 어떤 생성 공급자에도 전송하지 않는다. 통과 후에도 정제된 승인본만 짧은 만료 URL로 보낸다.
5. 원본(격리), 정제 참조본(프로젝트 private), 결과물(delivery)을 서로 다른 저장 경로와 권한으로 관리한다.

권장 보존은 차단/검사 실패 원본 24시간 이내 자동 삭제, 승인 참조 원본은 최종 생성 후 7일 또는 업로드 후 30일 중 이른 시점 삭제다. 사용자 삭제 요청은 즉시 접근을 철회하고 물리 삭제 SLA로 이어진다. 감사 로그에는 asset ID·판정·시점만 남기며 원본 미디어를 기록하지 않는다.

## 상태·증거

```text
draft → upload-quarantine → asset-scan → policy-check
      → reference-approved | rewrite | needs-review | blocked
      → storyboard-draft → awaiting-approval → queued
```

`delivery manifest`에는 참조 asset ID, 선택 목적, 동의 버전, 스캔·정책 판정, 공급자 전송 시점을 남긴다. 다음은 출시 전 증거다.

- 비식별 오리지널 참조 한 건이 검사·판정·스토리보드·실제 생성 입력까지 추적된다.
- 얼굴, 번호판, OCR 개인정보, 애니 스틸/제3자 영상, 오디오 fixture는 모두 차단 또는 검토 대기이며 공급자 호출이 없다.
